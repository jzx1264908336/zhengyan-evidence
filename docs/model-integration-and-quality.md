# 模型集成与回答质量改进

## 模型随产品交付

可以作为本地推理组件交付，当前已经通过 Ollama 集成到产品主链路。模型与 Web 服务为独立进程，统一启动入口；不需要云端 API Key。它不是浏览器直接加载的大文件，也不是本项目自行训练的权重。

实际导出的模型组件总计 **6,550,827,108 字节**。本次提交平台限制 30MB，因此不能把权重和源码一起放进该平台的小附件。小附件包含源码、启动/准备脚本、版本锁、许可证、真实测试记录；另行交付的离线目录包含权重缓存。也可由接收方首次下载模型，但可变标签下载后的版本必须重新核验。

离线目录：`outputs/offline-model`（不进入 Git）。已验证：8 个导出组件的大小和 SHA-256；使用只指向该目录的独立 Ollama 服务，在临时回环端口识别模型及 Q4_K_M 格式。没有把现有 Ollama 服务停止或配置改为公网；临时服务已在检查后关闭。未进行另一台新电脑的安装验收。

许可证、首次准备与离线配置见 [模型组件说明](../models/README.md)。已保留模型附带的 Apache-2.0 文本和原始归属，权重未修改。源码与模型分开并不表示模型未集成，而是将应用、运行时和权重按体积及运行条件交付。

## 效果和优化选择

当前 Qwen3.5 9B 能执行固定财报证据包的中文解释；此前实际出现过问题没有答全、归母/合并口径说明不直接、核算调整被误称异常、季度更新与年度说明混用，以及没有足够证据的因果扩展。不能因格式与数字通过就声称其语义能力全部通过，更不能声称已与大型云端模型进行同题能力对照。

本轮没有训练模型。先改善以下环节：

1. 按问题生成固定研究分节，每个分节有独立问题、事实、口径边界和证据包。
2. 模型按固定 key 返回正文，漏掉估值或行情等分节即失败；数值与对应证据包引用由程序附加，不由模型自由编造 ID。
3. 口径节必须解释归母不含少数股东损益，且分母要求限定在本产品现金覆盖比值；核算调整不自动等于异常。
4. 单独识别季度报告的原始版/更新版，引用两版原始字段，并与年度同行可比性说明分节。
5. 拦截无证据的共享原因、忽略峰谷先后顺序的最大回撤定义等已知错误；对否定句分别处理，避免误伤正确的限制表述。
6. 输出有实质内容但未通过校验时，只允许一次带问题说明的修正；总时间预算不增加，仍失败就显式失败，不改用规则冒充模型。

温度 0 与 0.2 在三个关键问题上进行小样本对照；该比较用于选择本产品运行参数，不是统计意义上的模型能力排名。两组都需要经过相同校验。未发现足够证据支持升温，保留默认温度 0、关闭思考模式。关闭思考模式是当前延迟预算下的运行选择，尚未证明优于开启思考模式。

只有在累积足够的高质量失败样本、经审核的目标答案及独立评估集后，才值得评估 LoRA 等微调。把少数演示问题训练进去会使演示更像成功，却不能证明泛化能力；目前不把财报数值写入模型权重，保持它们可更新、可追溯。

## 验证材料及边界

更新后的主问题集、改写回归组、参数对照记录分别保存在同目录的 JSON 文件中。改写组是开发期设计并用于回归的问题，不是严格盲测集。语义检查由 AI 辅助完成，候选人仍应亲自审核；任何通过数字、分节和引用范围校验的输出，都不能替代对整句话证据支持关系的判断。

公开线上站点仍为原 V2 财报核验版；本次模型能力在本地产品运行，公开托管环境无法直接连接接收方电脑的回环地址。提交说明必须保留这一运行边界。
